# دليل استخدام ChatPlatform
[English](HELP-EN.md) | [دليل المطور](DEVELOPMENT.md) | [التوسع](SCALABILITY.md)

هذا الدليل يصف الفرع التطويري عند المراجعة بتاريخ 27 نوفمبر 2026، وليس بالضرورة النسخة المنشورة على Fly.io. المنصة تعمل بـ ASP.NET Core 8 وSQLite وواجهة ويب عربية. لا ترسل أسرارًا أو بيانات عملاء في GitHub أو المحادثات.

## 1. الدخول والصلاحيات
افتح /login.html على عنوان الخادم عبر HTTPS. سجّل الدخول بالحساب الذي أنشأه المسؤول. تظهر لوحة العمل المناسبة للدور. لا توجد كلمة مرور افتراضية.
| الدور | العمل المسموح |
|---|---|
| SuperAdmin | /platform-admin.html: إنشاء الباقات والمؤسسات ومديريها، الاشتراكات والإيقاف وإعادة ضبط كلمة المرور وسجل العمليات. لا يقرأ محادثات المؤسسات مباشرة. |
| Admin | إعداد واتساب والقوالب والبوتات والمعرفة والتسويق وفريق المؤسسة والاشتراك. |
| Agent | معالجة محادثات المؤسسة والعملاء حسب صلاحيات API. التعيين للموظف ليس حدًا مستقلًا لرؤية المحادثات داخل المؤسسة. |
الخروج يلغي الجلسة. لا تشارك حسابات المدير. تفعيل MFA لحساب المالك لا يزال مطلوبًا قبل الإطلاق التجاري.

## 2. تسجيل المؤسسة وإدارتها
من لوحة مدير المنصة أنشئ باقة وحدد حصص الرسائل والموظفين والحسابات والبوتات والمقالات والميزات. أنشئ المؤسسة باسمها وحساب مدير فريد (3–64 حرفًا إنجليزيًا صغيرًا أو أرقامًا أو ._-)، وكلمة مرور قوية 14 حرفًا على الأقل وتاريخ انتهاء صالح. اختر الباقة. أنشئ حسابات الموظفين من /team.html داخل المؤسسة.
ابحث بمعرف المؤسسة أو الاسم الكامل أو اسم حساب المدير؛ كل صفحة تعرض حتى 100 سجل. عدّل الاشتراك أو أوقف المؤسسة عند الحاجة. الإيقاف يلغي الجلسات والرسائل المعلقة، ولا يحذف السجلات؛ لا يمكن استرجاع طلب إرسال وصل إلى Meta. لا يوجد دفع آلي؛ الأسعار إدارية.

## 3. واتساب
من /whatsapp.html استخدم الربط اليدوي: معرف WABA، معرف Phone Number ID، ورمز وصول صالح. معرف التطبيق ليس WABA. الخادم يتحقق من ملكية الرقم ويحفظ التوكن مشفرًا. إعدادات التحقق من webhook وسر التطبيق على الخادم فقط.
اختر التحقق لدى Meta ثم فحص الجاهزية؛ العضوية والاشتراك في التطبيق لا يثبتان التسليم. اختبر برسالة من رقم اختبار مسموح إلى رقم Meta، ثم تأكد من ظهورها في صندوق المحادثات، أرسل ردًا وتابع الإيصال. في حال تعذر الاتصال افحص العضوية والتوكن واشتراك messages وإعداد webhook. حافظ على رقم الاختبار الحالي. Embedded Signup معطل افتراضيًا؛ لا تفعّله قبل موافقة Meta واختبار الربط الحقيقي.

## 4. العمل اليومي
| الصفحة | الاستخدام |
|---|---|
| /index.html | مؤشرات المؤسسة والتنقل |
| /inbox.html | البحث، التصفية، الرد، التعيين للموظف، الحالة، غير المقروء، التحويل إلى الإنسان |
| /contacts.html | بيانات العملاء، المراحل والوسوم والملاحظات والنشاط الأخير |
| /bots.html | تصميم وحفظ ومحاكاة ونشر البوت |
| /knowledge.html | المقالات والبحث المحلي وتجربة النموذج الخاص إن سمح المسؤول |
| /marketing.html | قوائم العملاء والموافقة والشرائح والحملات |
| /reports.html | تقارير المؤسسة |
| /subscription.html | الحصص والاشتراك |
| /team.html | موظفو المؤسسة |
الرد النصي الحر يتطلب نافذة واتساب المسموحة؛ خارجها استخدم قالبًا معتمدًا حيث ينطبق. الحالة Queued ليست Sent، وSent ليست Delivered أو Read. DeliveryUnknown يعني أن نتيجة طلب الإرسال غير مؤكدة؛ راجع Meta قبل إعادة الإرسال.
يمكن إرفاق JPEG/PNG وMP4 وPDF وMP3/Ogg حتى 5 MiB؛ التسجيل الصوتي يعتمد على دعم المتصفح. لا توجد أرشفة دائمة للوسائط أو ضمان فحص كامل للبرمجيات الخبيثة.

## 5. البوتات
أنشئ مسودة، اسحب العقد أو اخترها، اربط المسار التالي/نعم/لا، اختبر ثم احفظ وانشر النسخة المحفوظة. العقد: بداية، شرط نصي، رد، انتظار، حفظ إجابة، تحويل لموظف، نهاية. الشرط يدعم الاحتواء والمطابقة وبداية النص.
مثال: بداية ← انتظار "ما اسمك؟" ← حفظ إجابة باسم name ← رد "مرحبًا {{name}}" ← نهاية. المحاكاة متعددة الرسائل (كل سطر رسالة) لا ترسل رسائل فعلية. هناك 40 عقدة كحد أقصى، وثمانية أسماء متغيرات، و500 حرف للقيمة، و30 دقيقة لاستئناف انتظار الإجابة. لا تحفظ كلمات المرور أو بيانات الدفع. نشر نسخة جديدة أو انتهاء المسار أو التحويل البشري يمنع استخدام سياق الانتظار السابق؛ قد تبقى قيمة منتهية في التخزين حتى تحديث الحالة. يوجد بوت منشور واحد لكل مؤسسة حاليًا. الإيقاف لا يضمن إلغاء كل الرسائل المؤجلة؛ استلام المحادثة بشريًا يلغي الرسائل الآلية المعلقة ولا يسترجع الطلبات الجارية.

## 6. المعرفة والتسويق
أنشئ المقالات وانشرها كي تدخل البحث المحلي. تجربة نموذج الذكاء الاصطناعي الخاص يدوية ومعطلة افتراضيًا؛ لا يوجد مزود مدفوع إلزامي أو رد AI تلقائي.
للحملة اختر الحساب، وتحقق من الموافقة الصريحة لكل عميل لذلك الحساب والقالب المعتمد. استعرض الشريحة واختر حتى 100 عميل ثم احفظ القائمة صراحة. الاستعراض لا يرسل رسائل. القائمة لقطة ثابتة؛ الموافقة تُراجع عند الجدولة والإرسال. STOP يوقف الموافقة ويلغي الإرسال المعلق بحسب الضوابط. التسويق معطل افتراضيًا إلى أن يفعّله المسؤول.

## 7. قواعد البيانات الخارجية
لا تتغير قاعدة المنصة. يضيف المسؤول التقني مصادر مستقلة لكل مؤسسة بواسطة إعدادات الخادم وIDatabaseAdapter (SQLite وPostgreSQL). حاليًا القراءة فقط وباستعلامات محددة مع معاملات parameterized؛ لا يوجد تنفيذ SQL حر أو كتابة أو مزامنة تلقائية أو ربط مباشر بعقد البوت. واجهة الإدارة البرمجية: GET /api/database-connections وPOST /api/database-connections/{id}/probe للمدير. لا تظهر كلمات المرور. واجهة مرئية واختبار PostgreSQL حقيقي مطلوبان. راجع SCALABILITY.md.

## 8. التشخيص والتشغيل
- 401: تحقق من تسجيل الدخول والجلسة؛ 403: تحقق من الدور والمؤسسة ولا تحاول تجاوز الصلاحيات؛ 409: تعارض الإصدار أو الحصة أو حالة الإعداد؛ 503: تعذر خدمة أو اتصال مؤقت.
- /health يوضح حالة الخادم والإصدار؛ /ready يختبر اتصال التخزين. لا يثبت أي منهما وصول واتساب.
- عند فشل إرسال أو إيصال، راجع حالة Outbox والوقت والحساب، ولا تكرر إرسالًا غامض النتيجة.
- لا تحذف /data. قبل ترحيل قاعدة الإنتاج اختبر نسخة احتياطية واستعادتها، واحفظ المفاتيح والأسرار خارج GitHub.
- لا تنشر لمجرد نجاح CI. تحقق من الإصدار المنشور واختبار Meta الحقيقي والصلاحيات والنسخ الاحتياطي.

## 9. حالة الاعتماد
نجحت CI المعزولة رقم 247 (run 46058912602) للمراجعة المرجعية 15d23313، بما فيها بناء Docker واختبار Graph الوهمي وعزل المؤسسات واختبار مليون سجل مؤسسة ومليون ربط مدير اصطناعي. لا يعني ذلك اعتماد مليون مؤسسة نشطة أو مليون حساب Meta. اختبارات الهاتف الفعلي، الضغط الشامل، الإنصاف بين المؤسسات، النشر الفعلي والتعافي التجاري لم تُعتمد بعد. راجع دليل المطور للتشغيل المحلي والاختبارات.

## التكاملات المحاسبية والدفع
من /integrations.html يستطيع مدير المؤسسة عرض الاتصالات المهيأة والاستعلام عن رصيد عميل أو فاتورة أو حالة دفع، وفحص قواعد البيانات. القراءة فقط؛ لا يتم خصم أو تحويل أموال أو تعديل قيود. يضبط المشغل المصادر الموثوقة وإعداداتها خارج الواجهة. راجع [وثيقة التكاملات](BUSINESS-INTEGRATIONS.md). ربط مزود حقيقي يحتاج وثيقته وحساب اختبار معتمد؛ ربط عقد البوت والكتابة لا يزالان غير متاحين.

عقدة «طلب استعلام مالي» في مصمم البوت تحول المحادثة إلى الوضع البشري وتضيف طلبًا للمدير في صفحة التكاملات؛ تختار المصدر والعملية المهيأة قبل النشر. لا ينفذ البوت الاستعلام بنفسه ولا يكشف الأرصدة أو الدفع. على المدير التحقق من العميل وإدخال المرجع صراحة. العودة إلى وضع البوت تغلق الطلب. لا تحصيل أو تسوية تلقائية.
